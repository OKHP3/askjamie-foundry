## Retirement and rollback gates

For each capability require all of the following before archiving a source:

- All inventoried files and Replit-only work have a reviewed destination,
  recovery archive or explicit accepted exclusion.
- Recovery is independently restored and checked against per-file hashes.
- Source rights, public-use boundary and attribution decisions are recorded.
- Configured GPT material and any approved project/thread material have a
  capture or an owner-accepted loss record.
- Portable behavior and chosen host pass the agreed cases; Jamie accepts limits.
- Existing website URLs remain valid and point to truthful access instructions.
  Test HTTP status, final location, navigation and mobile/browser behavior.
- Existing Notion anchors retain identity and history while routing to the new
  canonical source. Do not delete or merge them automatically.
- Replit parent source parity and child-specific environment dependencies are
  independently verified; local-only commits and meaningful state are preserved.
- A separate per-surface decision names exactly which repository/Repl/GPT will
  be archived, retained as reference or removed. Archiving is preferred to
  deletion; deletion is not implied.

Keep originals operational during migration. A failed pre-cutover check leaves
existing entry points and source repositories in place. After cutover, revert
only the reviewed reference/configuration changes and restore from the verified
snapshot. Record the restoration outcome and retain the failing version for
diagnosis. Revert a failed parent source integration through the protected PR
path; do not rewrite shared history.
