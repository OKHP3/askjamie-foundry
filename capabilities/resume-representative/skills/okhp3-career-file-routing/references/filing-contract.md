# Career filing contract

Use the workspace's owner-approved names and destinations. These purpose
examples help interpret a map and establish no default paths.

| Purpose | Material |
| --- | --- |
| Job search and applications | Opening research, fit notes, application packets, interview preparation, and exact submitted artifacts and receipts |
| Work-search evidence | Dated activity proof, maintained separately from application packets and official reporting |
| Approved résumé masters | Reusable owner-approved baselines with their revision and approval evidence |
| Role-specific résumé masters | Tailored working variants and reusable opening-specific masters with their own approval states |
| Historical résumé sources | Earlier source materials and prior versions kept as evidence |
| Career canon and strategy | Source-backed career claims and reference records in the canon, positioning and decisions in strategy |
| Employer and education records | Employment proof, academic records, transcripts, and related restricted material in their distinct homes |
| LinkedIn history | Exports, profile snapshots, drafts, and activity evidence within the private workspace |
| References and contacts | Private reference originals and contact records |

If an owner map distinguishes final outputs from supporting material, follow
that separation inside the verified opening. Preserve the exact submitted
version with its opening and reference it from related records when useful.
A résumé draft remains a draft until the owner approves it. A receipt can
document submission. Attendance, employer decisions, and official work-search
reporting require their own evidence.

## Filing record

Return one row per artifact or guidance record. Keep sensitive locators
inside the authorized workspace. Summarize sensitive gaps by category in
user-visible or shared reports when a precise locator would expose them.

- **Mode and artifact** with purpose, sensitivity, revision, and approval state.
- **Policy and destination evidence** with the represented person
  or verified person-specific scope, applicable host, provider account, root,
  exact folder or unresolved target, write authority, and observed access.
  Include observation time and inventory coverage.
- **Opening key and folder decision** with `not-applicable`, `reuse`,
  `create-needed`, or `unresolved`. State the exact or provisional basis.
- **Action state** with `proposed`, `verified`, `pending`, or `blocked`.
  Give the action taken or held, affected path or private locator, and why.
  State folder creation and artifact save separately if they diverge. For
  a new opening folder, record the logical-key guard or exclusive control.
- **Readback** with the saved item identity, expected parent identity, and
  payload match on the write surface. Report cloud presence and cloud
  payload match separately. Compare
  actual content or equivalent verified hashes before claiming a match.
- **Next check** for the smallest unresolved input, conflict, or access gap.

## Worked example

Example Works publishes requisitions R-42 and R-43 with the same role title.
The owner assigns R-42 and asks where to save its working résumé. The local
and cloud home names differ in accent encoding. The workspace map and folder
metadata establish that they are the same role-specific home. An existing
dated folder's private index identifies R-42. Report `reuse` and `proposed`
for that folder using its actual name. Keep R-43 separate. A later save needs
fresh identity, effective access, write authority, and readback.
