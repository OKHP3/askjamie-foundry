# Architecture and acceptance

The repeatable job is to turn an existing, approved career record and dated
surface observations into a field-level comparison and a review packet for
each existing publication owner. The package contributes an observation
contract, claim authority rules, field dispositions and a revision-specific
handoff. It needs no account, connector, script or fixed storage layout.

## Source release criteria

1. Match the same subject, surface, audience and field. Distinguish a directly
   observed live value, a dated capture and an access or identity gap.
2. Preserve dated claim authority, conflicting sources and explicit disclosure
   scope. Separate target positioning, historical experience and current status.
3. Permit audience-appropriate variants where the underlying facts agree.
   Route unresolved cases to a fact owner with the smallest verification step.
4. Separate the private ledger from a publisher-facing packet. Prevent
   restricted content and locators from leaking through either proposed copy
   or diagnostic metadata in the handoff.
5. Record exact proposed wording, revision, destination and owner. The
   procedure performs a read-only audit. Approval and post-edit read-back
   have distinct states and belong to the authorized downstream workflow.

Privacy, scope, authority and side-effect failures block a source release.
An analytical review can support source integration. Automatic triggering,
live quality, uplift and host acceptance require separate execution evidence.
