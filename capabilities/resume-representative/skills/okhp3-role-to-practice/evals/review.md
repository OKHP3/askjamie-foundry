# Role to Practice v1.0.0 release review

The package turns an opening and supplied career evidence into a qualification
map, a targeted next lesson, and a small practice exercise. The intended
release is portable source with analytical evidence.

## Candidate selection

| Candidate | Repeatable decision and artifact | Disposition |
| --- | --- | --- |
| Role-to-practice planning | Compare material requirements to the candidate's actual experience. Turn a gap into an official learning item and a testable exercise. Replan when the candidate corrects an assumption. | New companion skill. The initial concept needed criteria for employer requirements, learning progress, and proof from a lab. |
| Saved-opportunity triage | Identify saved listings, rank openings, and organize employer handoffs without conflating reposts and requisitions. | Use the existing AskJamie skill. Role to Practice starts from an opening or shortlist. |
| Application-status reconciliation | Match employer decisions and receipts to exact requisitions, then verify authorized record corrections. | Use the existing AskJamie skill. |
| Evidence-grounded résumé and interview work | Attribute real contributions and produce role-specific material that the candidate can defend. | Use Resume Representative for the narrative. This package supplies a practice plan and its evidence labels. |
| Workflow rehearsal from a known process | Identify roles, controls, paths, and expected results using a fictional system. | Keep as a worked example. The contract intake walkthrough supplies a test design. Evidence of a general workflow-building capability would require separate exercises and observed execution. |

Resume Representative is the canonical home because the workflow starts with a
candidate and an opening. Public content uses original instructions and
fictional examples. No vendor or host adapter is needed for the portable
planning procedure.

## Equilibrium review

The initial evidence, outcome, and safety/portability reviews used separated
read-only contexts. They found enough support for analytical source publication
and identified gaps in the development evidence. A separate disruptor tested
the original freeze and found ambiguous handling of lesson buttons that
enroll, instructions hidden in supplied material, and private channels within
live workspaces.

The revision added an effect check before a course action, an explicit stop
for mismatched accounts or items and unclear effects, pre/post verification,
source-agnostic authority rules, and a tabletop fallback when isolation is
unavailable. The fixture set now covers those controls and requires a named
official learning item with a relevant practice check. A separate negotiator
checked the revised guards against the counterexamples and clarified the
authority premise in the uncertain-readback case. See the [structured
decision and package fingerprints](review-1.0.0.json).

**Decision:** Approve with limits for analytical source publication.
The [development cases](evals.json) and [discovery rubric](discovery.md) were
inspected as source. The [live benchmark](../benchmarks/benchmark.json) is
`not-run`. The external unseen holdout, live activation, course actions, and
lab execution remain unverified. A future live evaluation needs observed
tool effects and persisted state as well as the agent's response.

## Distribution

This capability directory is canonical. For an authorized local Agent Skills
copy, use the merged revision and the complete package inventory, including
the license, references, and evaluation evidence. Install into an absent
destination or stop for comparison if one exists. Compare every file against
the canonical copy and record the source revision and destination. Recover
by removing only a newly created mirror or restoring a separately preserved
prior copy. Treat filesystem verification and host activation as separate
observations.
