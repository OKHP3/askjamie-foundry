# Career library and coaching skill extraction

## Outcome and candidate decisions

Produce three portable, source-only career capabilities with runtime-supplied
identity, sources and destinations. Canonical packages live in Resume
Representative; exact distribution mirrors live in Skillz's AskJamie family.
The methods were abstracted from owner-authorized career work. Private source
records, provider correspondence and transcripts are excluded from this release.

| Candidate | Decision and knowledge advantage |
| --- | --- |
| Lifetime career reference | New derived view: biography, reflection labeling, navigable career registers, bibliography and edition coverage. Preserve existing canon IDs/statuses. |
| Role master resumes | New: user-selected lane matrix, shared-fact invariants, edition lineage and single-source format parity. |
| Coaching engagement | New: one engagement owner, service clock, sponsor reporting versus privacy assertions, stateful intake and transcript-checked closeout. |
| Exact-job resume tailoring | Reuse existing targeted-resume workflow. It consumes masters and does not own corpus ingestion. |
| Audit one resume against earlier versions | Existing resume-evidence-reconciliation proposal owns that narrower read-only comparison; preserve its separate review. |
| Career filing and local/cloud reconciliation | Reuse career-file-routing, career-artifact-audit and record-location-reconciliation. A new folder taxonomy is not needed. |
| Email replies, document conversion, activity reconciliation and generic meeting notes | Compose existing domain/host tools when requested. Do not add another duplicate generic workflow. |

These are skills because their observable input/output contracts and repeatable
non-obvious decisions can guide another agent across different people, tools
and providers. They are not storage for one person's biography, portal
credentials or one provider's current terms.

Source intake and evidence canon are existing upstream owners, not new packages.
The initial broad library proposal was rejected for duplicating those owners.
The revised lifetime-reference package consumes their records and proposes
corrections upstream rather than writing a second ledger.

## Architecture and release question

Inputs: authorized source inventories or existing evidence library, selected
role lanes, provider evidence, current state and requested audience/output.
Outputs: a lifetime reference over the existing canon; role master editions;
private engagement brief and draft handoffs, respectively.

Boundaries: no invented qualifications, no hidden portal bypass, no implicit
profile edits, submissions or sends, no duplicate application owner, and no
publication of private career data. Missing evidence is explicit uncertainty.
No host-specific connector or renderer is assumed present.

Acceptance: distinct discovery boundaries; usable portable core; supplied
source/output record contracts; meaningful synthetic normal, edge and adversarial
cases; no private identifiers or secrets; no critical safety defect; validated
resource links/frontmatter; version-bound independent role reviews; exact mirror
inventory/hashes. A source release can be approved with limits without a claim
of measured uplift or production readiness.

Initial design gaps to test: false verification through generated prose,
learning-record inflation, unknown destination sharing, snapshot overwrites,
format claims without actual conversion, inferred salary answers, overstated
coach promises, local/web placement confusion and daylight-saving scheduling.

Evaluation status: cases and discovery queries are author-visible design
fixtures. Three independent role contexts and conditional adjudication will
review a frozen source set. No unseen holdout or matched with/without-skill
benchmark is claimed. Any behavioral exercise must be reported separately from
static package validation.

Source authority: owner authorization defines scope; current repository guidance
and the public Skill Foundry and Equilibrium Review packages define authoring and
review procedure. Historical workflow observations motivate synthetic regressions,
not public assertions about any candidate, employer, provider or service contract.

## Refinement from independent review

The frozen 0.1.0 set was rejected for material overlap with source intake and
career evidence canon. Evidence and outcome roles identified duplicate ownership
and a competing status vocabulary. Safety review identified timeout-after-commit
recovery, concurrent updates and secret-bearing source locator gaps. The integrator
accepted those findings rather than averaging role decisions.

The 0.2.0 candidate replaces the broad library with a lifetime derived view and
adds token-free references, inspect-before-retry, create-if-absent and exact-version
update controls. Initial review applies only to historical hashes. A fresh frozen
0.2.0 review is required before source publication or installation.

## Final bounded source decision

The 0.2.0 frozen core received approve-with-limits from three separated review
roles. Conditional falsification tested three compound contract-level objections
without a surviving blocker. A fresh adjudicator approved draftable source
publication and local source installation, preserving all live-evidence limits.
The [version-bound review record](career-library-review-2026-11-09.json)
contains decisive evidence, historical rejection, current core hashes and limits.
The [mirror manifest](career-library-skills-sync-2026-11-09.json) records exact
file inventories. Full raw reviewer outputs remain in the authorized private
task workspace; the public record contains generalized methods and synthetic cases.
