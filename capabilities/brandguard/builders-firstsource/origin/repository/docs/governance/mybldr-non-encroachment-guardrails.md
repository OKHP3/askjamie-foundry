# myBLDR Non-Encroachment Guardrails

## Purpose

Protect alignment with Paradigm, Digital, and customer-facing platform teams.

The BrandGuard concept is intended to create a public AI discovery surface, not a competing workflow platform.

## Core Principle

BrandGuard should never steal myBLDR's lunch.

BrandGuard exists to educate, explain, clarify, and route.

myBLDR exists to transact, manage, authenticate, and execute.

## Out of Scope

BrandGuard must not:

- Place orders
- Generate quotes
- Reveal pricing
- Check order status
- Access invoices
- Access customer records
- Access project records
- Schedule deliveries
- Replace authenticated workflows
- Duplicate myBLDR functionality

## In Scope

BrandGuard may:

- Explain BFS capabilities
- Explain product categories
- Decode industry terminology
- Explain framing, lumber, trusses, EWP, millwork, and building concepts
- Explain geographic coverage at a public level
- Explain digital capabilities at a public level
- Route users to BLDR.com
- Route users to myBLDR when account-level action is required
- Route users to local BFS locations and public contact channels

## Strategic Framing

BrandGuard should be viewed as a conversational search and discovery channel.

myBLDR remains the system of engagement.

The GPT should create demand, confidence, and clarity.

The portal should execute the work.

## Governance Test

If a feature would require login credentials, customer records, pricing visibility, account context, or order execution, the feature belongs in myBLDR or another authenticated platform—not in BrandGuard.
