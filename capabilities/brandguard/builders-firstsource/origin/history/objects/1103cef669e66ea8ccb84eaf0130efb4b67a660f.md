## Repo layout (standard)
- `src/corpus/` — public-only, normalized markdown topic files (your “public corpus”)
- `prompts/` — the instruction spine (identity, tone, ethics, routing rules)
- `eval/` — test harness prompts + rubrics (normal + edge cases)
- `build/` — generated packs for upload (Knowledge Pack / Prompt Pack / Eval Pack)
- `ops/` — release checklist, governance notes, templates
- `gpt_manifest.yaml` — wiring registry (links + version + lifecycle)

---

## Operating principles (BrandGuard rules)
1) **Public-only**: Everything must be attributable to public sources.  
2) **Honest & grounded**: Positive-but-honest, acknowledging strengths and critiques without spin.  
3) **Route to official channels**: When the user needs real-world action (branch contact, investor materials, official statements), route to **BLDR.com** and/or official channels.  
4) **No speculation**: If uncertain, say so and point to reputable sources.

---

## Build / release workflow (high-level)
1) Update `src/corpus/` and `prompts/`
2) Rebuild pack files into `build/`
3) Run `eval/` regression prompts (log results)
4) Update `CHANGELOG.md` + bump version
5) Tag a release
6) Upload updated packs into the Custom GPT / Workbench as needed
