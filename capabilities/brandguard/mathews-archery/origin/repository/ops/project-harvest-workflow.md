The Project coordinator inventories only the selected Project and maintains the stable source-to-intake registry. Each per-source Work intake is temporary. Its useful outputs survive in durable files and the Notion catalog; the intake is not a permanent continuation destination. A newly seeded intake does not convert the original Chat history natively.

## Per-source lifecycle

1. **Receive complete input.** Verify the intended local Project, host, source title/URL/ID and intake ID. Read active repository guidance and preserve owner changes. Accept Jamie's pasted chunks in order and wait for the standalone `END OF LEGACY THREAD` marker. Record attachments, Project instructions/shared sources, capture method and unknown history. For supported captures, record pagination and item/content-part clipping; a terminal page is not proof of complete text. Never read private application session stores.
2. **Extract useful context.** Preserve consequential human wording, decisions, corrections, alternatives, rationale, uncertainty and unfinished work. Keep roles, ordering and rich-element ownership. Distinguish historical assertions, current verified facts, proposals and unknowns. A scoped block count or source census does not establish a whole-Project semantic percentage.
3. **Preserve artifacts locally.** Save original captures and useful original payloads in owner-controlled durable storage, with hashes and format checks. Keep private raw chats, account identifiers and full crosswalks outside Git. Put reviewed portable artifacts in the proper local repository folders. Keep original corpus pairs intact unless a supported revision requires paired QA. Generate mechanical companions with `python3 ops/extract-knowledge-text.py --write` and check them with `python3 ops/extract-knowledge-text.py`. A new approximation does not establish original-file identity.
4. **Deduplicate and organize.** Compare with existing repository and relevant Notion material; classify units as already durable, complementary, new, conflicted, excluded with reason or missing. Do not equate topic/title overlap with byte or semantic equivalence. Retain useful methods, questions and next actions without importing repeated prose. Stop deeper recovery when marginal effort exceeds expected value, with an honest remaining-value record. Report the owner's greater-than-60-percent floor and greater-than-80-percent goal only against a defensible identified-value denominator; unknown overall value remains unknown.
5. **Route to Notion and verify coverage.** Fetch the intended destination, search for duplicates, inspect database schema when applicable, make the smallest authorized write and read it back. Validate local artifacts, provenance, relative links, privacy, original hashes and `git diff --check`. Confirm useful wording, decisions, uncertainty, unfinished work and required assets have durable destinations. Record the exact archive-ready rationale and clear applicable source-specific holds. Missing useful assets or substantive unassessed content block this gate. No percentage may be invented to pass it.
6. **Archive the legacy CHAT thread.** Only after steps 1-5 pass and applicable holds are cleared, archive the exact selected source ID through supported tools. Record the result and verify archive membership. Never delete the source or archive the Project container as a substitute. An uncertain or failed archive result stops closure; do not retry a mutation blindly.
7. **Commit and push artifacts to GitHub.** Commit the reviewed task-owned files and source-archive evidence using the existing branch/PR convention. Push, then verify the exact remote commit and expected files. Attach any created PR. Save the push receipt durably, including commit identity and verification result. If commit, push or remote verification fails, retain the Work intake and report the precise action, target and blocker; do not erase local artifacts or automatically undo the source archive.
8. **Archive the WORK intake thread.** Only after step 7's push is confirmed, preserve the final source/intake crosswalk, source archive receipt, artifact paths/hashes, Notion receipt IDs, commit/push proof and unresolved-work references in durable records. Archive the exact temporary intake through supported tools and verify its archive membership. If self-archiving ends the run, the coordinator records the post-action receipt without reopening the intake. Never delete it. Retain the intake if any prerequisite fails.

## Archive gate

A source becomes a candidate only after observed useful user content, decisions, next actions, and artifacts are durably portable. Missing useful assets or substantive unassessed content block readiness. Incidental images can be omitted only with a precise reason. Unresolved source claims may remain unresolved if their values, uncertainty, and next actions are preserved.

Assign one actor per archive action. Jamie's clarified sequence places legacy Chat archiving at step 6, GitHub commit/push at step 7 and intake archiving at step 8. Local preservation and Notion readback precede source archive; verified remote delivery precedes intake archive. Older generic guidance requiring a GitHub push before source archive is superseded for these intakes.

Current source holds are not cleared by this procedure's existence. Archiving individual threads does not preserve or remove Project-shared sources. A private raw archive alone does not establish useful semantic extraction. Do not reopen a completed archived intake merely to deliver a later workflow update.

## Handoff contract

Record the batch, exact source boundary, source and intake IDs, source links, captures and hashes, artifact origins, meaningful exclusions, value denominator and limits, source dispositions, local validation, Notion write/readback receipt IDs, legacy archive result, commit/push proof and intake archive result. Keep private identifiers in the owner-controlled manifest and use a privacy-safe pointer in broader repository outputs. Keep extraction, source preservation, native conversion, GitHub delivery and both archive actions as separate statuses. The workflow applies per source; it does not close the Project coordinator or archive other sources automatically.
