## Suggested repo layout
- `/prompts/` — instruction blocks, tone, behavior rules, few-shots  
- `/src/` — source corpus (notes, drafts, transcripts, references)  
- `/eval/` — tests + rubrics (what “good” looks like)  
- `/build/` — compiled outputs (knowledge-pack, prompt-pack, eval-pack)  
- `/docs/` — supporting docs (policies, decisions, diagrams)

## Workflow (hybrid method)
1. Update source materials in `/src` and prompt assets in `/prompts`.
2. Compile updated packs into `/build/` (keep file count low; keep structure high).
3. Upload packs to the **Custom GPT** and/or the **Workbench Project** as appropriate.
4. Record changes in `CHANGELOG.md` and tag a release when shipping behavior changes.
